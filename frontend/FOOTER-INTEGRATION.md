# Beam wordmark footer integration

## Project structure

This is an existing **Vite + React + TypeScript + Tailwind CSS v4** application. No project recreation, Next.js migration, extra React provider, external image service, or web font CDN is needed.

- Application components: `src/components/`
- Reusable shadcn-style UI components: **`src/components/ui/`**
- Shared component import: **`@/components/ui/beam-wordmark-footer`**
- Host stylesheet: **`src/styles.css`**
- Shared utility: `src/lib/utils.ts` (`cn` using `clsx` + `tailwind-merge`)
- shadcn configuration: root `components.json`
- Alias: `@/*` → `src/*` in TypeScript and Vite.

In this source-root project, `/components/ui` means `src/components/ui`, not a second root-level `components` directory. Keeping reusable primitives there gives the shadcn registry/CLI a predictable destination, preserves the supplied `@/components/ui/...` import, and separates generic components from product-specific data and routing.

The existing global tokens remain intact. shadcn-compatible semantic tokens and Tailwind v4 `@theme inline` mappings were added. `tw-animate-css` is included for future shadcn components; the footer itself only depends on React and its scoped stylesheet.

To add future primitives, run this **from the existing project directory**:

```bash
npm ci
npx shadcn@latest add button
```

The project already has `components.json`; **do not rerun `init` or scaffold over the application**. For an entirely new Vite project instead, create the React/TypeScript template, install Tailwind v4 with `@tailwindcss/vite`, configure the `@` alias, import Tailwind in its global CSS, then run `npx shadcn@latest init`. Those steps have already been handled here.

## Files and responsibilities

- `src/components/ui/beam-wordmark-footer.tsx`: supplied reusable footer, its helper exports, props, pure fitting/beam functions, built-in SVG social icons and scoped CSS.
- `src/components/ui/demo.tsx`: supplied standalone `w-full` demo with the original defaults. It is not mounted in the TrustHeart app.
- `src/components/TrustHeartFooter.tsx`: actual brand, colors, real links, React Router integration, Lucide source shortcuts, legal disclaimer, demo status and back-to-top action.
- `src/App.tsx`: renders exactly one `TrustHeartFooter` after the route outlet. The previous footer was removed.
- `src/styles.css`: TrustHeart-specific `.trustheart-footer` / `.thf-*` adjustments and semantic tokens. Retired footer styles were removed.

## Data and state

The actual footer uses:

- Brand/company: **TrustHeart 3D** (no invented LLC).
- Wordmark: **TrustHeart**, fitted to its container and cropped/faded at the baseline.
- Font: the existing locally hosted Manrope.
- Colors: midnight navy with a blue beam, matching the heart treatment; lime is retained for research/demo status.
- Internal routes: Home, Start analysis, Results, Model insights, Methodology, About.
- External links: the supplied UCI dataset, original licensed Sketchfab model, and CC BY 4.0 license.
- Source shortcut buttons instead of fabricated social accounts. Replace the `sources` prop data only when actual project social URLs are supplied.
- Existing educational/research disclaimer, simulated-demo notice and no-patient-data-storage context.

No new global state is introduced. Visibility, fitted typography and reduced-motion flags stay in local component state. Pointer coordinates stay in a ref; requestAnimationFrame updates CSS variables rather than React state.

Internal links call React Router `navigate` and prevent the anchor's document reload for ordinary clicks, preserving the in-memory analysis session. Modified clicks retain native browser behavior. External source shortcuts open safely with `rel="noreferrer"`.

## Small adaptations to the supplied component

The visual design and original exported helpers/props were retained. Integration-specific additions:

1. `onLinkClick` accepts an optional **third event argument**, so the host can intercept internal links. Existing two-argument callbacks remain compatible.
2. An optional `children` slot preserves the clinical disclaimer and controls **inside the one footer landmark**.
3. Pointer glow is updated after the pointer ref in stationary/reduced-motion mode. This fixes the original native-listener ordering issue and correctly clears the glow on pointer leave.
4. Animation pauses when offscreen or the document is hidden. Reduced-motion mode holds the beam still and removes reveal/hop motion.
5. Larger touch targets, visible keyboard focus, safe custom-icon lookup, and explicit inherited credit colors avoid conflicts with host CSS.
6. Back to top moves keyboard focus to the header brand as well as scrolling.

No stock imagery was added: the supplied footer has **no image slots**. Its light, grain and wordmark are generated by CSS/live text, and source shortcut icons use the already installed Lucide package.

## Responsive behavior

Three columns on desktop; the copyright/source/credit block spans the full row below 760 container pixels, followed by two link columns. At the smallest sizes, the utility controls wrap and back to top gets a full row. The wordmark is remeasured after fonts load and on container resize. Only the intended bottom crop is applied; letters do not overflow horizontally.
